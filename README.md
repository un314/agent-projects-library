## 按场景分组

**客服与营销**
01 电商智能客服 · 06 直播带货 · 11 舆情监控 · 13 电商运营

这组解决的都是"对外触达"问题：怎么接待、怎么吆喝、外界怎么说、货怎么卖。共同点是强依赖实时数据流与知识库，且都需要人机协同。

**企业知识与办公**
02 Dify 智能体助手 · 04 论文写作 · 17 面试模拟 · 18 论文精读

这组解决的是"知识的生产与消费"：把文档变成可问答的知识库，把写作与培训变成可控流程。技术核心都是 RAG + 多轮对话。

**财务与金融**
03 金融分析 · 05 财务报销审核 · 15 财富管理

这组对准确性要求最高，都采用"规则 + 检索 + 模型"的组合，而不是让模型裸奔。05 与公司财务场景最贴近。

**医疗健康与生活服务**
07 糖尿病助手 · 10 饮食规划 · 12 营养师 · 14 旅行规划 · 16 搬家装修

这组是典型的 C 端个性化顾问，共性结构是"采集用户约束 → 检索专业知识 → 生成方案 → 输出清单/指南"。

**研发与专业服务**
08 游戏测试 · 09 法律咨询

08 偏自动化执行，09 偏专业知识输出，共同点是都需要强证据链（截图、判例）。

## 哪些适合直接复用

**优先落地（改造量小、收益明确）**

- **02 Dify 智能体助手**：最快能跑起来的企业助手。AI 能力交给 Dify，后端只写常规 CRUD 与权限，一周内可出可用版本。适合作为公司第一个 AI 应用。
- **18 PaperAI 论文精读**：文档解析 → 切块 → 向量 → 带引用问答，这套链路可直接改造成合同审阅、标书解析、制度问答，是通用性最强的一份。
- **01 电商智能客服**：意图 → 情感 → 转人工的三段式路由，换知识库即可用于售后、政务、内部 IT 支持。RAG 知识库管理模块可独立抽出。
- **05 财务报销审核**：与公司财务场景直接对口。"先规则后模型"的分层设计值得照搬，避免模型在金额、发票这类硬指标上出错。

**改造后可用（需补业务数据或外部接口）**

- **11 舆情监控**：监测闭环通用，但采集层要按目标平台重写。适合做品牌/竞品监测。
- **13 电商运营**：Agent 任务表 + 工作流分文件的工程结构很好，先做通一条工作流再复制。
- **04 论文写作**：骨架可改成方案书、报告、标书生成器，只需替换章节模板与 Prompt。
- **06 直播话术**：意图 → 策略模板表的结构很轻，可用于客服实时辅助；但弹幕源接入是主要工作量。
- **03 金融分析**：多 Agent 编排与混合检索值得借鉴，但需要真实行情与财务数据源。

**参考价值为主（不建议直接落地）**

- **08 游戏测试**：依赖具体客户端与图像识别，环境适配成本高。
- **07 / 10 / 12 健康类**：工程不难，但有医疗合规与责任边界问题；10 与 12 定位重叠，取一即可。
- **09 法律咨询**：专业准确性要求高，需真实案例库与法律审核。
- **14 / 16 生活服务**：偏 C 端场景，与公司主业关联弱，但 LangGraph 编排写法值得学习。
- **15 财富管理**：涉及投顾资质与合规，短期不建议碰。
- **17 面试模拟**：最轻量，可作为内部培训工具快速试验，但商业价值有限。

## 技术共性

18 个项目高度同构，可以抽出一套公共脚手架：

- **前后端**：Vue 3 + TypeScript + Vite + Element Plus / Arco Design；FastAPI + SQLAlchemy + Pydantic
- **Agent 编排**：以 LangGraph 为主（状态定义 + 节点 + 条件边 + 图构建），少数用 ReAct 或自研编排器
- **RAG**：ChromaDB 为主，生产环境用 Milvus；向量检索 + 重排 + 混合检索的组合反复出现
- **存储**：MySQL / PostgreSQL + Redis；原型阶段常用 SQLite
- **部署**：Docker Compose + Nginx，部分含前后端 Dockerfile

也就是说，掌握**一套 LangGraph + RAG + FastAPI + Vue 的模板**，再配上领域知识库与 Prompt，就能覆盖这里绝大部分项目。真正拉开差距的不是架构，而是每个领域的知识库质量与业务规则细节。
