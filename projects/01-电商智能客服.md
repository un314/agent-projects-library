# 01 电商智能客服

> 生产级电商智能客服系统：LLM + Agent + RAG + 意图识别 + 情感分析，面向售前咨询、订单查询、退款与投诉场景。

## 项目定位

一套可直接对标商用的智能客服中台。核心不是"聊天"，而是把一次用户咨询拆成可路由的任务：能答的自动答、该查的去查、该转的转人工。

## 要解决的问题

- 人工客服成本高，无法 7×24 覆盖
- 大量重复咨询（物流、退换货、优惠）占用坐席
- 复杂问题需要多步操作（查订单、查商品、发起退款），普通问答机器人做不到
- 用户带情绪时缺少差异化响应，容易升级为投诉
- 客服数据散落，无法沉淀为知识库与分析报表

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Pinia + Vite |
| 后端 | FastAPI + SQLAlchemy + Pydantic |
| 存储 | MySQL 8（业务）、Redis（会话）、Milvus + etcd（向量） |
| AI | LLM（OpenAI 兼容接口）、Embedding、Reranker（cross-encoder）、NLU 意图分类、情感分析 |
| 部署 | Docker Compose + Nginx |

## 核心流程与架构

五层架构：客户端层（Web / H5 / 小程序 / 企业微信）→ 网关层（Nginx、API Gateway、WebSocket Proxy）→ FastAPI 服务层（Chat / Intent / Agent / Search）→ 业务逻辑层（对话管理、意图分类、情感分析、Agent 调度）→ AI 服务层（LLM、Embedding、RAG Engine）。

一次对话的处理链路：

1. 消息经 WebSocket 或 HTTP 进入，完成鉴权与会话绑定
2. 意图识别：关键词规则兜底 + LLM 深度理解，输出六类意图（商品咨询 / 订单查询 / 退款 / 投诉 / 转人工 / 闲聊）与置信度
3. 情感分析：正 / 中 / 负 + 强度分，负面情绪触发安抚话术与优先转人工
4. RAG 检索：查询向量化 → 向量召回 top_k → 重排 → 拼接上下文
5. 回复生成：带快捷问题与结构化卡片返回
6. 复杂场景转人工：生成工单号并移交坐席，保留完整上下文
7. 全量落库，供分析看板统计意图分布、满意度、转人工率

Agent 采用 ReAct 架构，工具集为：知识库检索、订单查询、商品查询、退款处理、转人工。工具以插件形式注册在 Agent 基类上，新增能力只需加一个 Tool。

## 可复用点

- **三段式路由**（意图 → 情感 → 转人工）是客服类系统的通用骨架，换个知识库就能用在售后、政务、银行
- **RAG 知识库管理**：上传、切块、MD5 去重、向量化、删除，是独立可搬的通用组件
- **Agent 基类 + 工具注册**：把"能查什么"与"怎么对话"解耦，扩展成本低
- **数据模型**：users / sessions / messages / intents / knowledge / products / orders，可直接作为客服系统起点
- **会话与消息设计**支持 sender_type（user / bot / agent）与转接状态机

## 实现难度

**高**。全栈 + 三类中间件（MySQL / Redis / Milvus），89 页文档包含完整建表、后端服务、前端组件与 Docker 编排。若只复用意图路由与 RAG 两个模块，难度降为中等。
