# 02 基于 Dify 的企业级智能体助手

> 以 Dify 为 AI 能力底座的企业级助手：后端做编排与权限，AI 能力全部外置到 Dify 平台。

## 项目定位

一套"薄后端 + 强平台"的企业助手方案。业务系统不直接对接模型，而是通过 Dify 的 API 统一获得对话、知识库问答和 Agent 执行能力，后端只负责用户、会话、意图与数据。

## 要解决的问题

- 企业自建 LLM 应用门槛高：模型接入、Prompt 管理、知识库、向量化都要自己写
- 多个业务线各建一套 AI，无法统一权限、计费与知识资产
- 缺少统一的会话记录、知识库管理与工具注册入口
- Prompt 与模型频繁变更，代码侧改动成本高

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| AI 平台 | Dify 0.6.x（LLM 应用、RAG、Agent、知识库） |
| 后端 | FastAPI 0.109 + SQLAlchemy 2 + Pydantic 2 + Python 3.11 |
| 前端 | Vue 3.4 + Vite 5 + Element Plus 2.5 + Pinia |
| 存储 | MySQL 8（业务）、Redis 7（会话缓存）、向量库（Dify 侧） |
| 其他 | LangChain 0.1、JWT 鉴权、Docker |

## 核心流程与架构

分层：前端（聊天、知识库管理、用户中心）→ FastAPI（路由、认证中间件、限流）→ 业务层（对话管理、意图识别引擎、情感分析引擎、会话管理）→ AI 能力层（Dify：LLM / RAG / Agent）→ 数据层。

主链路：

1. 前端 POST 消息 → 后端校验身份
2. 意图识别引擎给出分类（规则匹配 + 置信度阈值，低置信度回落到通用问答）
3. 情感分析引擎给出标签（积极 / 中性 / 消极）
4. 按意图路由到不同服务：普通问答走 Dify 对话接口，知识类走 RAG 检索，任务类走 Agent 执行
5. 保存会话与消息，返回响应（支持流式）

RAG 子流程：向量编码 → 向量检索 → 相关性判断（无结果则退化为直答）→ 重排 → 构建 Prompt → LLM 生成。知识库支持创建、文档上传、内容 hash 去重、切块、删除。

Agent 服务维护一张工具表（名称、描述、类型、参数 schema），执行时按名称分发到具体实现，并记录 agent_logs。

## 可复用点

- **Dify 作为 AI 中台的架构范式**：最快把"企业助手"跑起来，且不锁死在某家模型
- **意图路由表**：intent → service 的映射配置，新增场景只改配置
- **知识库 CRUD + 去重 + 切块**：独立服务，脱离 Dify 也能用
- **JWT 鉴权 + Redis 会话 + 限流**：企业级后端的标准三件套
- **agent_tools / agent_logs 表设计**：工具注册与执行审计

## 实现难度

**中**。AI 复杂度被 Dify 吸收，代码量集中在常规后端能力上，99 页文档几乎覆盖全部源码。适合作为公司第一个落地的 AI 应用。
