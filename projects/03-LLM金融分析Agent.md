# 03 基于 LLM 的金融分析 AI Agent

> 多 Agent 协作的智能投研系统：编排器 + 投研 / 风控 / 策略三类 Agent，配套 RAG、LLMOps 与 DataOps。

## 项目定位

面向投研场景的 Agent 中台。用户用自然语言提问，系统自动拆解任务、并行调用多个专业 Agent，最后汇总成一份可读的分析结论，并对整个模型调用过程做可观测。

## 要解决的问题

- 金融数据体量大、更新快，人工分析跟不上
- 财报、研报、法规分散，检索与交叉验证成本高
- 单一模型给出的结论缺乏风控视角，容易片面
- 模型调用成本、延迟、失败率不可见，无法优化
- 行情与财务数据需要稳定的 ETL 管道

## 技术栈与平台

| 类别 | 选型 |
| --- | --- |
| LLM | Qwen / DeepSeek / GPT-4（OpenAI 兼容接口） |
| Embedding | BGE-large-zh / text-embedding-3-large（1536 维） |
| 向量库 | ChromaDB（本地）/ Milvus（生产） |
| Agent 框架 | LangChain + 自研编排器 |
| 后端 | FastAPI + Python 3.11 |
| 前端 | Vue 3 + TypeScript + Vite（深色主题） |
| 存储 | PostgreSQL + TimescaleDB（时序）、Redis |
| 数据管道 | Prefect（ETL 编排） |
| 监控 | Prometheus + Grafana |
| 部署 | Docker + Docker Compose |

## 核心流程与架构

1. 用户输入查询 → 编排器做意图分类与任务拆解
2. 拆出的子任务并行下发：投研 Agent 做基本面与估值分析，风控 Agent 做异常与风险扫描，策略 Agent 生成操作建议
3. 每个 Agent 先走 RAG：查询改写 → 混合检索（向量 + 关键词）→ 重排 → 组织证据
4. 各 Agent 输出结构化结论，编排器汇总成报告并附来源
5. LLMOps 记录每次调用的 token、耗时、模型与状态，前端提供监控面板

RAG 层专门做了查询改写模块，解决金融术语与口语表达不匹配的问题；混合检索兼顾语义与代码/指标类精确匹配。

DataOps 用 Prefect 编排行情、财报、公告的采集与入仓，TimescaleDB 承担时序数据的聚合查询。

## 可复用点

- **多 Agent 并行编排器**：任务拆解 → 并行执行 → 汇总，是最通用的复杂 Agent 骨架
- **混合检索 + 查询改写 + 重排**：检索质量的三个关键动作，可直接移植到任何专业领域知识库
- **LLMOps 监控表设计**：模型、token、延迟、成本、成功率，做 AI 应用必备
- **DataOps 管道**：定时 ETL + 时序库，适合行情、日志、指标类数据
- **统一 LLM 调用接口**：屏蔽不同厂商差异

## 实现难度

**高**。92 页，文档覆盖编排器、四类 Agent、RAG 全链路、监控与数据管道，需要真实行情/财务数据源才能跑通。若只取编排器 + RAG 骨架，难度为中。
