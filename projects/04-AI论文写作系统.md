# 04 AI 论文写作系统

> 多 Agent 协作的长文档生成系统：LangGraph 把写作拆成选题、大纲、文献、撰写、润色五个阶段，支持 SSE 流式输出与版本回滚。

## 项目定位

把"写一篇结构化长文"这件事工程化。不是让模型一次性生成全文，而是用状态机把写作拆成可回退、可重跑的节点，每个节点由一个专职 Agent 负责。

## 要解决的问题

- 选题与大纲要反复推敲，人工成本高
- 文献检索与引用格式容易出错
- 长文一次性生成质量差、逻辑容易断
- 多轮修改后版本混乱，无法回溯
- 生成过程黑盒，用户等待焦虑

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 后端 | FastAPI 0.104+、Python 3.10+ |
| Agent | LangChain 0.1 + LangGraph 0.0.20+（状态图编排） |
| 检索 | ChromaDB 向量库 + RAG 文献检索 |
| 存储 | SQLite / PostgreSQL |
| 前端 | Vue 3.4 + Pinia + Element Plus + Vite |
| 交互 | SSE 流式响应 |

## 核心流程与架构

LangGraph 状态流转：

1. **选题推荐 Agent**：根据研究领域与关键词产出候选选题及理由
2. **大纲生成 Agent**：按论文类型生成章节结构
3. **文献检索 Agent**：RAG 召回相关文献，生成引用条目
4. **内容撰写 Agent**：按章节逐个生成，携带大纲与已写内容作为上下文
5. **润色优化 Agent**：语言表达、术语一致性、格式规范检查
6. 每阶段结果写入版本表，支持回滚与分支重跑

前端通过 SSE 接收增量内容，实时渲染生成过程；论文、章节、引用、版本各自独立建模。

## 可复用点

- **LangGraph 状态定义 + 图构建**：条件边、循环、人工介入点的写法，是最值得抄的骨架
- **分章节生成 + 上下文累积**：解决长文一致性问题的通用手法
- **版本管理表**：任何 AI 生成类产品都需要
- **SSE 流式输出**：改善长任务体验的标准做法

同一套骨架可以直接改造成方案书、标书、研究报告、周报生成器，只需替换 Prompt 与章节模板。

## 实现难度

**中高**。83 页，代码以 Agent 与工作流为主，没有复杂中间件。难点在 Prompt 设计与状态流转的边界处理，不在工程规模。
