# 05 财务报销审核系统

> AI Agent 驱动的报销审核：单据识别 + 规则引擎 + RAG 制度检索 + 多 Agent 协作 + 审批流自动化。

## 项目定位

把财务报销的审核动作结构化：机器先做能规则化的部分，模型再做需要理解的部分，最后给出结论与风险等级并驱动审批流转。

## 要解决的问题

- 人工审核单据效率低，高峰期积压
- 不同审核人尺度不一，标准不统一
- 重复报销、超标、虚开发票等风险识别能力弱
- 制度条款分散，审核时难以快速引用依据
- 审批流转靠人催，状态不透明

## 核心流程与架构

1. **单据识别**：上传发票 / 收据，抽取发票号、金额、日期、抬头、税号、明细
2. **规则引擎校验**：对照企业财务制度做硬性校验——限额、时限、科目匹配、发票重复、连号异常
3. **RAG 知识检索**：召回相关制度条款与历史相似案例，为判断提供依据
4. **多 Agent 协作**（LangGraph 编排）：识别 Agent → 校验 Agent → 风险评估 Agent → 审批 Agent，逐级传递结构化结论
5. **风险分级**：低风险自动通过，中风险转人工复核，高风险拦截并说明理由
6. **审批流转**：按规则自动推进节点，记录每一步操作
7. **统计分析**：按部门、科目、时间维度出报表

设计上的关键取舍是"先规则后模型"：能确定的用规则，避免模型幻觉；规则覆盖不到的语义判断（如事由合理性）才交给 LLM。

## 可复用点

- **规则引擎 + RAG + Agent 的三层结构**：最贴近企业内控场景的通用范式
- **单据字段模型**：发票、明细、审批记录、风险项，可直接用于费控系统
- **审批流状态机**：状态、节点、操作人、意见
- **风险分级策略**：低风险放行、中风险复核、高风险拦截
- **制度知识库**：制度文档切块入库，审核时自动引用条款

## 实现难度

**高**。105 页，是 18 份文档中最厚的一份，含 OCR 识别、审批流、统计报表与完整前后端。若暂不做 OCR、只做结构化表单录入，难度降为中高。
