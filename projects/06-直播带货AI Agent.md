# 06 直播带货 AI Agent

> 实时弹幕分析 + 话术推荐：WebSocket 接入弹幕流，意图识别后用 RAG 检索话术库，2 秒内把建议推给主播。

## 项目定位

主播身边的实时副驾。系统不听主播说话，而是盯着弹幕，判断"这条弹幕值不值得回应、该怎么回应"，然后把话术送到主播屏幕上。

## 要解决的问题

- 直播弹幕量大、节奏快，主播无法逐条阅读
- 购买意向、价格疑虑、竞品对比等高价值信号容易被淹没
- 负面情绪若响应不及时，会迅速扩散
- 优秀话术沉淀在老主播个人经验里，无法复用
- 直播结束后缺少复盘数据

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 实时通道 | WebSocket（多平台弹幕接入） |
| 后端 | FastAPI + Python |
| Agent | LangGraph（状态机多步编排）+ LangChain |
| 检索 | RAG：商品知识库 + 话术库向量检索 |
| 存储 | MySQL + Redis |
| 前端 | Vue 3 + TypeScript + ECharts |

## 核心流程与架构

LangGraph 把弹幕处理拆成一条流水线：

1. **接收弹幕**：WebSocket 流入，做去重与清洗
2. **意图识别**：LLM 判定购买意向 / 疑问 / 负面情绪 / 普通互动，并给出置信度
3. **知识检索**：按意图检索对应知识——促销话术、产品参数、价格策略、安抚话术、互动模板
4. **话术生成**：结合上下文生成一句可直接念的话术，避免模型幻觉
5. **策略推荐**：输出优先级与动作。策略模板按意图配置，例如负面情绪 → 高优先级 → 安抚情绪 + 解决方案 → 真诚道歉、提供补偿、转移注意力
6. **实时推送**：结果经 WebSocket 推回主播端，端到端延迟控制在 2 秒内
7. **看板统计**：弹幕趋势、情感分布、转化漏斗

低置信度（低于 0.6）时自动降级为"观察等待"，不打扰主播，这是很实用的产品细节。

## 可复用点

- **意图 → 策略模板表**：极轻量的配置结构（intent / priority / action / tips），可迁移到客服实时辅助、销售话术提示
- **流式处理链路**：采集 → 清洗 → 判定 → 检索 → 生成 → 推送
- **话术库建设方法**：把优秀话术向量化，按场景分类检索
- **实时看板**：ECharts + WebSocket 的增量更新方式

## 实现难度

**中高**。60 页，工程结构清晰。主要难点在弹幕数据源接入（各平台协议不同），若用模拟弹幕流验证，落地难度为中。
