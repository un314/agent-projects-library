# 07 糖尿病患者 AI 健康助手

> 慢病管理 Agent：整合血糖、饮食、用药、运动多维数据，用 LangGraph 编排"症状分析 → 知识检索 → 方案生成 → 风险评估"。

## 项目定位

面向糖尿病患者的私人健康管家。核心价值不是聊天，而是把碎片化的自我管理数据连成一条可执行、可预警、可复诊的闭环。

## 要解决的问题

- 数据碎片化：血糖、饮食、用药、运动散落在不同 App 或纸面记录
- 缺乏个性化：通用建议无法匹配个人血糖波动规律
- 复诊间隔长，两次就诊之间的异常难以及时干预
- 依从性差，缺少持续提醒与正向反馈
- 医患之间缺少结构化数据共享

## 技术栈与平台

| 技术 | 用途 |
| --- | --- |
| LLM | 对话、症状分析、方案生成 |
| LangChain | LLM 调用封装、链式编排 |
| LangGraph | Agent 工作流状态机 |
| RAG + ChromaDB | 糖尿病指南、营养学知识向量检索 |
| FastAPI | REST API + WebSocket |
| SQLAlchemy + SQLite | 数据持久化 |
| Vue 3 + TypeScript + Element Plus + Pinia | 前端 |

## 核心流程与架构

Agent 工作流四节点：

1. **症状分析**：读取近期血糖序列、饮食与用药记录，识别异常模式（餐后峰值、夜间低血糖）
2. **知识检索**：从医学指南与营养库召回对应处置建议
3. **方案生成**：输出个性化饮食（含碳水与 GI 计算）、运动、用药提醒方案
4. **风险评估**：给出风险等级，触发预警通知

功能模块包括血糖监测与趋势分析、智能饮食管理、用药提醒与药物相互作用检查、运动指导、周期健康报告、AI 问诊、可视化仪表盘、医患数据共享。

## 可复用点

- **指标录入 → 分析 → 建议 → 预警**四段式，可迁移到血压、体重、睡眠等任何健康监测场景
- **健康数据模型**：指标、记录、方案、提醒、报告
- **预警规则配置**：阈值 + 持续性判断（单次超标与连续超标区别对待）
- **报告生成模板**：周期汇总 + 趋势图 + 建议

## 实现难度

**中**。94 页，页面较多但技术栈轻（SQLite + 本地向量库），无重中间件。真正的门槛在医疗合规与建议准确性，工程本身不难。
