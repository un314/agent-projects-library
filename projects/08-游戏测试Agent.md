# 08 游戏测试 Agent

> 自动化游戏测试：主控 / 执行 / 分析三类 Agent 协作，PyAutoGUI 操作游戏、截图取证、LLM 判定异常、RAG 比对历史 Bug。

## 项目定位

把"人点游戏找 Bug"这件事交给 Agent。执行层模拟真实操作，分析层用模型判断画面是否异常，最后产出带截图和重现步骤的结构化缺陷报告。

## 要解决的问题

- 手工测试效率低、覆盖不全、回归重复劳动
- 复杂游戏状态难以用脚本穷举
- Bug 描述不规范，开发难以复现
- 历史 Bug 无法复用，同类问题反复提交
- 测试进度不可见

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| Agent | LangGraph 多 Agent（master / executor / analyzer） |
| 自动化 | PyAutoGUI（Windows / macOS / Linux 跨平台） |
| 检索 | RAG：历史 Bug 库 + 游戏文档 |
| 后端 | FastAPI（异步、多任务并行）、SQLite |
| 实时 | WebSocket 推送进度与 Bug 列表 |
| 前端 | Vue 3 |
| 报告 | PDF / HTML 导出 |

## 核心流程与架构

1. **任务创建**：配置测试范围、路径策略、时长、截图频率
2. **主控 Agent**：拆解任务，规划探索路径，调度执行与分析
3. **执行 Agent**：识别可交互元素，模拟点击/按键，遍历界面路径，按节奏截图并记录日志
4. **分析 Agent**：读取截图与日志，用 LLM 判断是否异常并分类（卡死、错位、数值错误、崩溃）
5. **RAG 比对**：检索历史 Bug 库做去重与相似度判断，避免重复提单
6. **实时推送**：WebSocket 把进度、Bug 列表推送到监控面板
7. **报告导出**：生成含截图、日志、重现步骤的 PDF / HTML 报告

## 可复用点

- **屏幕操作 + 截图 + 视觉判断**的 RPA 式 Agent 骨架，可迁移到 UI 自动化测试、系统巡检、批量数据录入校验
- **三 Agent 分工**（调度 / 执行 / 分析）职责边界清晰，是复杂自动化的标准拆法
- **Bug 去重检索**：向量比对历史缺陷，避免重复
- **报告模板**：结论 + 证据 + 复现路径

## 实现难度

**高**。72 页。难点不在代码量，而在真实环境的稳定性：图像识别受分辨率、渲染、延迟影响大，PyAutoGUI 缺乏可靠的元素定位，需要大量适配。
