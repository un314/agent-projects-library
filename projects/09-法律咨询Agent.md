# 09 法律咨询 Agent（LegalMind）

> 基于案例库的法律问答与文书生成：RAG 召回相似判例，LangGraph 编排意图分流，输出带依据的回答与标准化文书。

## 项目定位

法律领域的专业问答助手。回答必须有出处，文书必须合格式，这两点决定了它不能只靠模型自由发挥。

## 要解决的问题

- 法律服务成本高，基础咨询门槛大
- 案例检索靠人工翻库，耗时且容易漏
- 法律文书格式严格，非专业人士难以起草
- 模型容易编造法条与判例，专业场景不可接受
- 复杂法律问题需要多轮澄清

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 后端 | FastAPI、Python、JWT 鉴权 |
| Agent | LangChain + LangGraph（工作流编排） |
| 检索 | ChromaDB 向量库 + RAG（可接领域 Embedding 与 Reranker） |
| LLM | 通用大模型，可选法律领域微调模型 |
| 前端 | Vue 3 + Vite + Tailwind CSS |

## 核心流程与架构

1. **意图 Agent**：判定用户诉求属于法律问答、文书起草还是案例检索
2. **检索 Agent**：把问题向量化，从案例库召回相似判例与法条
3. **QA Agent**：基于检索结果生成回答，逐条标注依据来源，遵循"无依据不回答"
4. **文书 Agent**：按模板生成起诉状、答辩状、合同等，填充当事人、事实、请求、法律依据
5. **对话记忆**：维护多轮上下文，支持追问与澄清

知识库管理支持案例的增删改查与向量索引重建。文档总结经验了几条关键调优：chunk 大小 500–1000 字符、使用领域相关 Embedding、混合检索（向量 + 关键词）、接入 Reranker 重排、Prompt 中强化"无依据不回答"。

## 可复用点

- **意图分流 + 模板化文书生成**：任何"问答 + 出文"类业务都能套用
- **依据标注与拒答策略**：专业领域可信度的核心设计
- **RAG 调参经验**：chunk 划分、混合检索、重排，这几条对本项目其他知识库场景同样适用
- **案例库模型**：案由、事实、裁判要旨、法条引用

## 实现难度

**中高**。67 页，工程结构标准。真正的门槛是法律语料的准确性与责任边界，技术实现本身可控。
