# 10 智能饮食规划助手

> 体检数据 + 口味偏好 → 7 天个性化食谱 + 购物清单，RAG 增强营养建议。

## 项目定位

把"我该吃什么"这个问题，从模糊建议变成一份可执行的周计划和一张能直接下单的购物清单。

## 要解决的问题

- 普通人缺乏营养学知识，看不懂体检报告里的异常项
- 三高、肥胖等人群需要针对性饮食，但网上建议千篇一律
- 忌口、过敏、烹饪能力等现实约束常被忽略
- 知道该吃什么，但不知道怎么买菜、怎么安排一周

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 后端 | FastAPI + Python |
| Agent | LangGraph + LangChain（多步推理工作流） |
| 检索 | RAG + 营养学知识库 |
| 数据库 | MySQL 8.0（utf8mb4） |
| 前端 | Vue 3 + TypeScript + Element Plus + Pinia |

## 核心流程与架构

1. **录入体检指标**：身高体重、血压、血糖、血脂等，系统自动识别异常项并给出健康评估
2. **设置口味偏好**：口味、忌口、过敏食物、烹饪偏好
3. **RAG 检索**：按异常项与偏好召回营养学知识（食材营养、搭配禁忌、烹饪方式）
4. **生成 7 天食谱**：在营养均衡约束下生成每日三餐，附带热量与营养素估算
5. **输出健康分析报告**：综合给出饮食与生活建议
6. **生成购物清单**：按品类自动汇总食材与用量
7. **营养师对话**：随时追问，基于同一份用户档案回答

## 可复用点

- **结构化输入 + 约束生成**：体检项作为硬约束、口味作为软约束，是"个性化方案生成"的通用套路
- **清单类输出**：食谱 → 购物清单的聚合逻辑，可迁移到备餐、采购、物料清单
- **健康档案模型**：指标、偏好、方案、清单
- **报告模板**：异常项 + 建议 + 依据

## 实现难度

**中**。33 页，是 18 份文档中体量最小的之一，技术栈常规、无重中间件。与 12 号 AI 营养师高度相似，可合并为一套营养域方案。
