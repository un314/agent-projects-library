# 11 AI 智能舆情监控系统

> 多平台舆情采集 + LLM 情感分析 + 热点追踪 + 分级预警 + 自动报告。

## 项目定位

持续盯着外部声音的系统。把散落在微博、新闻、知乎、论坛的讨论收集起来，判断情绪走向、识别热点，超过阈值就报警。

## 要解决的问题

- 人工搜索效率低，耗时耗力
- 覆盖不全，容易遗漏重要信息
- 响应滞后，负面舆情发酵后才被发现
- 分析不深，只做关键词统计，缺少语义理解
- 缺少可复用的监测报告

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 前端 | Vue 3.4 + Element Plus + ECharts + Pinia + Axios + Vite |
| 后端 | FastAPI 0.104+ |
| Agent | LangChain + LangGraph（工作流） |
| LLM | GPT-4 级别模型（情感与语义理解） |
| 检索 | RAG 知识库 |
| 存储 | MySQL 8.0 + Redis 7.0 |
| 实时 | 异步采集 + WebSocket 推送 |

## 核心流程与架构

数据流：采集 → 清洗 → 特征提取 → 情感分析 → 热点识别 → 预警判断 → 存储 → 可视化。

1. **实时监控**：异步任务 7×24 抓取各平台内容，Redis 做缓存与去重
2. **情感分析**：LLM 输出情感极性与强度分（如 -0.9 表示强烈负面），而非简单正负二分
3. **热点追踪**：NLP 聚类 + 时间序列分析，识别话题热度上升趋势
4. **预警通知**：按规则生成 alerts，分等级（critical 等高危级别），WebSocket 实时推送
5. **报告生成**：LLM + 模板引擎自动产出舆情分析报告
6. **可视化**：ECharts 展示情感分布、话题趋势、来源占比

数据模型上，分析结果与预警记录分离，预警关联具体结果并带已读状态，便于闭环处理。

## 可复用点

- **外部信号监测闭环**：采集 → 语义分析 → 分级 → 推送 → 归档，可直接用于品牌监测、竞品监控、政策跟踪
- **情感强度分设计**：比三分类更有信息量
- **预警规则 + 等级 + 已读状态**：告警类系统的标准模型
- **报告自动生成**：模板 + 模型填充
- **异步采集 + 缓存去重**：采集层的通用结构

## 实现难度

**中高**。71 页。主要工作量在采集适配（各平台反爬与格式差异），分析与展示部分难度适中。
