# 12 AI 营养师 Agent

> 四段式多 Agent 流水线：健康分析 → 营养规划 → 食谱生成 → 质量审核，ChromaDB 承载营养知识库。

## 项目定位

比 10 号饮食规划更强调"多 Agent 分工 + 生成后自审"。每个环节由独立 Agent 负责，最后一个 Agent 专门挑前面生成内容的毛病。

## 要解决的问题

- 专业营养师成本高、服务覆盖面有限
- 通用建议不个性化，忽略健康指标与口味
- 单次生成容易营养失衡
- 用户偏好需要长期学习与记忆

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 后端 | Python 3.10+、FastAPI 0.104+、SQLAlchemy 2.0、Pydantic 2.0 |
| Agent | LangChain 0.1 + LangGraph 0.1（多 Agent 工作流） |
| 向量库 | ChromaDB 0.4+ |
| 数据库 | MySQL 8.0 |
| 认证 | JWT（python-jose） |
| 前端 | Vue 3.4 + Vite 5 + Element Plus 2.4 + TailwindCSS 3.4 + Pinia + Vue Router + Axios |

## 核心流程与架构

LangGraph 编排的四个节点：

1. **健康分析 Agent**：解析体检报告，提取关键指标，标记异常项
2. **营养规划 Agent**：根据健康状况与偏好确定营养目标（热量、蛋白、碳水、GI）
3. **食谱生成 Agent**：产出每日三餐方案，附食材与做法
4. **质量审核 Agent**：校验营养均衡性、忌口冲突、可行性，不合格则回退重生成

配合功能：健康报告解析、个性化食谱、每日膳食规划、知识库问答、用户偏好管理。

## 可复用点

- **生成 + 自审的双段模式**：审核 Agent 是提升生成质量最划算的投入，适用于任何内容生成场景
- **多 Agent 职责切分**：分析 / 规划 / 生成 / 审核，边界清楚、可单独替换
- **偏好学习的数据结构**：把用户偏好作为生成约束持久化
- **完整的工程骨架**：JWT、路由、Pinia、Axios 封装齐全，可直接作前后端模板
