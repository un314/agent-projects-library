# 14 智能旅行规划 Agent

> LangGraph 六节点工作流：解析需求 → 搜索景点 → 获取天气 → 生成行程 → 优化路线 → 生成回复，带条件边与重试循环。

## 项目定位

把"帮我规划一次旅行"变成一条可控的多阶段流水线。每一阶段是独立节点，阶段之间可以回退重排，最后输出一份可执行的完整攻略。

## 要解决的问题

- 行程规划耗时，需要同时权衡预算、偏好、距离、天气
- 信息分散在攻略、地图、气象等多个来源
- 用户需求模糊，需要边问边明确
- 行程生成后难以修改，改一处牵连全局

## 核心流程与架构

`AgentState` 贯穿全流程，六个节点：

1. `parse_requirements`：解析目的地、天数、预算、同行人、偏好
2. `search_spots`：景点检索工具，结合知识库召回候选
3. `fetch_weather`：天气工具，按日期获取预报
4. `generate_itinerary`：按天编排行程，考虑动线与用餐
5. `optimize_route`：路线优化，压缩通勤、平衡强度
6. `generate_response`：生成自然语言攻略与结构化行程

图上的条件边决定走向：`is_trip_planning_complete` 判断是否完成，`should_retry` 控制是否回到重排节点。这是 LangGraph 最典型的"循环 + 条件分支"用法。

工具层按领域拆分：`spot_tools`、`weather_tools`、`route_tools`，新增数据源只需加一个 Tool。

## 可复用点

- **带条件边与重试循环的 LangGraph 范式**：18 份文档中编排写法最标准的样本，适合作为团队学习与复用基线
- **AgentState 状态设计**：把阶段产出都放进状态，节点之间只传状态
- **工具插件化**：景点 / 天气 / 路线各自独立
- **多阶段规划骨架**：换成"选址 / 排产 / 配送"等业务同样成立
