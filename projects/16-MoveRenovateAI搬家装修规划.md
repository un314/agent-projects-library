# 16 MoveRenovateAI 搬家装修规划 Agent

> 双 Agent 系统：搬家规划 + 装修规划，各自独立状态机，共用一套前后端与知识库。

## 项目定位

一个项目里放两条完整的规划流水线。搬家和装修虽是两件事，但都需要"清点 → 排序 → 估费 → 出执行指南"这套结构。

## 要解决的问题

- 搬家容易漏东西，打包顺序混乱，费用不透明
- 装修预算、材料、施工阶段缺少整体规划
- 网上攻略通用性强，不匹配具体房型与需求
- 执行阶段缺少可照做的清单

## 核心流程与架构

两套独立状态：`MovingAgentState` 与 `RenovatingAgentState`。

**搬家 Agent**（六节点）：
1. 解析搬家需求（房型、人数、时间、预算）
2. 生成物品清单（按房间类型自动枚举）
3. 规划打包方案（按优先级与房间排序，生成箱号与标签）
4. 计算搬家费用（路线、车型、人力）
5. 生成还原指南（新家拆箱与摆放顺序）
6. 生成最终回复

**装修 Agent**：解析需求 → 风格与预算匹配 → 材料清单 → 施工阶段排期 → 输出方案。

两个 Agent 各自有 `graph.py`、`nodes.py`、`state.py`，互不干扰；对外暴露统一的 run 接口。

## 可复用点

- **双状态机并存的组织方式**：一个应用承载多条业务流水线，互不耦合
- **清单 + 排序 + 估费 + 执行指南**输出结构：可直接迁移到活动执行、实施交付、项目搬迁等场景
- **按房间 / 按阶段的枚举模板**：结构化清单生成的标准做法
- **Agent 单例 + run 封装**：调用方无需关心图内部结构
