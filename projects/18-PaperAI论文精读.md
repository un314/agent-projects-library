# 18 PaperAI 论文精读 Agent

> PDF 解析 + 结构化提取 + 全文问答 + 笔记管理，RAG 支撑带来源标注的问答。

## 项目定位

把一篇论文变成可交互的知识对象。上传之后能问、能摘、能记，回答必须指到原文位置。

## 要解决的问题

- 论文阅读慢，尤其是不熟悉领域的方法与公式部分
- 图表与公式难以理解，缺少解释
- 读完记不住，笔记散落在各处
- 通用问答工具容易编造，无法核对原文

## 技术栈与平台

| 层 | 技术 |
| --- | --- |
| 后端 | FastAPI + Python |
| Agent | LangChain + LangGraph |
| 检索 | Chroma 向量库 + RAG |
| 存储 | PostgreSQL + Redis |
| 前端 | Vue 3 + TypeScript + Arco Design |
| 解析 | PDF / HTML 上传与结构化提取 |

## 核心流程与架构

1. **上传解析**：PDF 或 HTML 入库，提取标题、作者、摘要、关键词
2. **章节切分**：按章节结构切块，保留层级与页码，作为引用定位依据
3. **向量入库**：切块嵌入后写入 Chroma
4. **全文问答**：意图识别 → 检索 → 生成回答，并标注来源片段
5. **深度理解**：一句话概括核心贡献、方法拆解、实验结论、局限性分析
6. **笔记管理**：创建、分类、关联原文位置
7. **导出**：摘要与笔记导出为结构化文档

## 可复用点

- **文档解析 → 切块 → 向量 → 带引用问答**全链路：公司做文档知识库、合同审阅、标书解析最直接的模板
- **来源标注**：让回答可验证，是专业场景的刚需
- **章节感知的切块策略**：比固定长度切块更利于长文档问答
- **笔记与原文位置关联**：知识沉淀类产品的通用设计

## 实现难度

**中**。44 页，规模适中。主要工作量在 PDF 解析（版式多样、公式图表处理），问答与前端部分较为常规。
